# Mac側への追加実装引き継ぎ

## 素材の接続

追加素材のルートは `ios_flip_v1/` です。`manifest.json` と各SHA-256を確認し、`clips/start_flip.mp4`、`stills/prepare_bottom.png`、`icons/AppIcon1024.png` を取り込んでください。既存の `ios_cycles_v1/` は継続使用します。

開始時は `prepare_bottom.png` の姿勢から `start_flip.mp4` を1回だけ再生します。映像は1.25秒、30フレームです。時刻0〜29/24秒の画像で構成されます。動画が正常に終端へ達した後、落砂側の共通位相時計を0にして `remaining_100.mp4` へ切り替えます。反転映像自体をリピートしません。

カメラ・背景・床の反射は映像に含まれます。既存の「画像または動画全体に180度回転を適用する」実装を外してください。5:6の縦横比を維持し、反転中にも切り取らない表示にします。素材の表示変換は既存のBT.709色管理と合わせます。

## 開始処理の契約

開始操作に一意な `startAttemptID` を割り当て、一つの実行主体（MainActorなど）で以下の状態を管理します。既存のタイマーモデルの名前・APIに合わせて実装してください。準備状態を永続ストレージへ保存しません。

| 状態 | 動作・許可する遷移 |
|---|---|
| idle / finished | 開始可能。表示モードと指定時間を記憶し、attemptを作る |
| checkingPermission | アラーム許可を確認。連打は無視。失敗はidleへ戻して表示 |
| loadingAssets | 映像と静止画の存在・準備完了を確認。未完了を成功にしない |
| flipping | 残り時間を減らさず、反転を一度だけ表示。正常な再生終了でのみ次へ |
| reservingAlarm | 一意な予約IDを使って予約を実行。二重実行しない |
| running | 予約成功を確認後に開始を確定。時計を正とし、映像時間は使わない |

各await後にattempt IDと現在状態を確認し、取り消された古い処理が新しい開始へ干渉しないようにします。開始ボタンの無効化だけでなく、開始処理入口でも実行中を検査します。

アラームに設定した締切時刻と、残り時間の基準となる締切時刻を同じ値にします。予約のAPI呼び出し完了までの時間を無条件に付け足したり、反転開始時刻をタイマーの開始時刻に使ったりしないでください。1秒タイマーでは予約遅延も見えるため、既存予約APIの完了結果と締切を確認して表示を確定します。

予約結果を待つ間は反転映像の最終フレームを保持し、準備状態を維持します。予約成功の確定とともに既存の落砂映像を位相0から開始します。失敗した場合は準備用静止画へ戻します。

再生完了と失敗通知、開始操作、非アクティブ通知が同時に到着しても、同じattemptから予約を複数回呼ばないようにします。遅延した再生終了通知は、attemptが一致し、現在状態がflippingであるときだけ採用します。

## 取り消し・再開・失敗

- checkingPermission / loadingAssets / flipping中に非アクティブになった場合、attemptを無効にして再生を停止し、開始準備を取り消します。次の復帰で自動開始しません。
- reservingAlarmに入った後は、取消要求だけで予約失敗と決めつけません。予約IDで結果を照合し、必要なら確定した予約を解除してからidleへ戻します。再試行で重複予約しないよう、予約中のattemptを解決するまで新しい開始を拒否します。
- 素材の欠損、読み込み・再生エラー、許可拒否、予約失敗を成功イベントへ変換しません。問題を表示し、開始前の残り時間と表示モードへ戻します。
- 一時停止からの再開は既存の再開経路で処理し、反転しません。アプリ復帰や表示切り替えでも反転しません。
- 数字表示から開始した場合も、準備中だけ反転映像を表示し、開始確定後または取消後に元の数字表示へ戻します。
- Reduce Motionが有効ならflippingを省略します。予約成功後、通常の落砂表示または元の数字表示を開始します。存在しない動画を「再生成功」にしたり、予約結果を省略したりしません。

## 1×1アイコンと既存ウィジェット

`icons/AppIcon1024.png` をSUNA本体のAppIconへ割り当てます。正方形1024px、不透明RGB、角丸マスクなしです。アプリと同じBlender砂時計の静止画であり、タップすると通常のアプリ起動になります。

既存コードで「1×1」と案内していた小サイズウィジェットの誤った案内・専用化を整理し、元の小・中サイズの対応を復元してください。このアイコン用のWidget Extensionや常時動画再生を追加する必要はありません。

アプリ内の案内文案：

> ホーム画面に砂時計アイコンを追加するには、Appライブラリで「SUNA」を探し、アイコンを長押しして「ホーム画面に追加」を選びます。すでにホーム画面にある場合は、そのアイコンを使えます。タップするとSUNAが開きます。

## 実機での確認

| 操作 | 期待結果 |
|---|---|
| 1秒タイマーを新規開始 | 反転中は1秒のまま。反転後の計測とアラームが一致 |
| 3分タイマーを新規開始 | 反転後から3分を計測。正常に終了表示・通知へ |
| 開始を連打 | 反転と予約は1回のみ |
| 数字表示で開始 | 反転を見せてから数字表示へ戻る |
| 一時停止→再開 | 反転せず残り時間から続行 |
| 表示切り替え・通常の復帰 | 新たに反転しない |
| 反転途中で背景へ | 開始を取り消し、復帰後も未開始 |
| 予約途中で背景へ | 予約結果を照合し、重複・孤立予約を残さない |
| Reduce Motion | 反転を省略し、予約成功を確認して計測開始 |
| 動画・静止画欠損、再生エラー、予約失敗 | エラーが分かり、開始成功として保存されない |
| ホーム画面のSUNAアイコン | 新しい砂時計が小さくても判別でき、タップで起動 |
| 小・中ウィジェット | 既存の配置・表示・復帰との互換性を維持 |

すべて確認した後にReleaseビルドを作り、iPhone 14 Pro Maxへ更新します。ユーザーの指示により、このWindows側の作業はBlender素材の生成・検証までです。アプリの組み込み・署名・インストール・実機テストはMac側が担当します。
